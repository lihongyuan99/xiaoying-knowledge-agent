# 02 方案与动态决策

## 调用流程

```text
问题 + 可选历史
      ↓
模型输出一个 JSON 动作
      ↓
search_documents / read_document / finish
      ↓
结构化观察（命中、原文或错误）
      ↓
模型读取最新观察并选择下一动作
      ↓
结果与引用校验 → 返回 / 反馈模型修正 / 达到上限停止
```

真实模式没有预设流程骨架。`OpenAICompatibleModel.decide()` 每轮收到原始请求、全部工具观察和剩余步数；`KnowledgeQAAgent` 只负责执行动作、维护 Trace、校验结果和限制预算。模型可补充检索、读取任一命中文档、在失败后换动作或结束。

真实验证发现部分响应会在一次输出中连续给出多个 JSON 动作。解析器只执行第一个完整对象，绝不预先回放后续动作；后续决策必须等待新的工具观察。首个对象后的非 JSON 内容仍会报错。

## 工具

- `search_documents(query, top_k)`：本地字符 n-gram/关键词评分，返回文档元数据、评分和定位片段。片段只用于选择原文。
- `read_document(doc_id)`：返回完整原文。只有该工具成功返回的文档进入可引用集合。
- 故障注入位于工具执行器，不改变业务资料，用于可复现的失败测试。

检索采用标准库实现，避免为小型合成库引入向量模型和外部服务。优点是确定、离线、易替换；缺点是语义泛化有限，改写和跨语言检索弱于嵌入检索。

## 冲突与资料不足

提示协议要求模型读取冲突双方原文，分别陈述事实并引用；未提供适用范围和优先级时返回 `needs_clarification`，填写缺口与追问。版本日期仅作为元数据展示，不作为自动裁决规则。

检索无命中时模型可换关键词补充检索；仍无依据则返回 `insufficient_information`。上下文问题由模型先生成可独立理解的检索 query，避免只拿“那上海呢？”检索。

## 引用防护

`finish` 不直接等于成功返回。程序检查：

1. 状态和必填字段是否合法；`completed` 必须有引用。
2. 被引用文档是否在本轮成功读取。
3. `quote` 是否为对应原文的逐字连续片段。
4. 追问和资料不足状态是否包含必要说明。

失败会作为结构化观察反馈给模型，模型可修正；达到上限则返回 `max_steps_exceeded`。这能阻止错误引用和未读取即回答，但不能数学上证明自然语言答案的每个推断都完全正确，仍需测试和人工审查。

## 技术取舍

- **原生 Python，不使用 Agent 框架**：题目规模小，原生循环足以展示模型决策，减少框架黑盒和安装成本。
- **OpenAI 兼容 HTTP 接口**：标准库即可接入，模型与供应商可配置；依赖服务支持 JSON object 响应。
- **JSON 文档库**：合成资料短且数量少，便于审查、替换和复现。
- **离线 Mock 单独实现**：只作为流程测试替身，不与真实模型混称，也不把其输出作为模型能力证据。
- **简短 rationale**：Trace 记录行动依据而非隐藏思维过程，满足可审计要求。

## 执行预算

默认最多 8 个模型动作，工具失败和无效结束也计步。可用 `--max-steps` 调整。模型 API 或 JSON 解析失败返回 `model_error`，不会自动切换到 Mock。
