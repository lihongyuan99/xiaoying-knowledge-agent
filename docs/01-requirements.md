# 01 需求与成功标准

## 用户与目标

用户是需要查询企业制度或产品规则的员工。系统接收当前问题及可选对话历史，在合成 FAQ/制度库中检索并读取原文，输出可靠回答、文档 ID、版本日期、逐字引用、资料缺口和任务状态。

可靠性优先于回答率：没有依据时不回答，资料冲突时不擅自选择，引用必须能直接支持答案。

## 范围

已实现：

- 本地 JSON 文档库；检索与原文读取两个独立工具。
- OpenAI 兼容真实模型适配器，每轮根据最新观察重新决策。
- 明确标注的离线流程 Mock，供无模型环境验证。
- CLI、执行步数上限、故障注入、引用校验、完整 Trace。
- 自动化测试及七组离线实际运行记录。

不在范围内：图形界面、线上部署、多 Agent、生产级 Runtime、真实企业数据和向量数据库。

## 验收矩阵

| 验收点 | 成功标准 | 主要证据 |
|---|---|---|
| 明确答案 | 回答年假提前 3 个工作日申请，引用 D04 原文 | `examples/01_clear_answer.json` |
| 文档冲突 | 同时呈现 D01/30 天和 D02/15 天，说明缺口并追问，不任选其一 | `examples/02_conflict.json` |
| 资料外问题 | 对带宠物上班问题返回资料不足，不编造规定 | `examples/03_out_of_scope.json` |
| 改写后的相似问题 | 将“酒店每晚最多能报多少钱”定位到住宿标准并回答 500 元 | `examples/04_paraphrase.json` |
| 上下文追问 | 将“那上海呢？”改写成独立住宿检索查询 | `examples/05_followup.json` |
| 工具失败 | 读取 D03 失败后明确 `tool_error`，不伪造答案或引用 | `examples/06_tool_failure.json` |
| 替换资料 | D03 改为 600 元后，答案与引用同步变为 600 元 | `examples/07_replaced_document.json` |
| 单一来源 | 只有 D01 时可回答 30 天，不虚构 D02 冲突 | `tests/test_agent.py` |
| 引用防护 | 非逐字引用被拒绝并反馈，修正后才完成 | `tests/test_agent.py` |
| 执行上限 | 达到上限明确返回未完成状态 | `tests/test_agent.py` |

## 证据边界

上表不带 `real_` 前缀的 examples 由 `offline_mock` 生成，用于证明流程、工具协议、输出约束和测试可执行性。真实模型验收已使用 `deepseek-v4.1-flash` 完成 8 组运行，索引见 `examples/real_manifest.json`：明确答案与冲突形成不同 ReAct 路径，并覆盖资料外、改写、上下文追问、工具失败恢复、资料替换和执行上限。评估详情见 `docs/03-evaluation.md`。
